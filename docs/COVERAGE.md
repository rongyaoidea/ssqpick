# 预算覆盖助手

## 它解决什么

“这一期至少中一个奖”的概率，主要取决于蓝球覆盖：蓝球命中一个就至少六等奖。
把同样的预算拆成多注、让蓝球尽量不同，比反复买同一个蓝球更能提高任意奖频率。

它不预测号码，也不改变每注 2 元的期望回报。覆盖提高的是中奖频率，不是收益率。

## 规则

- 每注 2 元；单次最多 50 注（100 元）。
- 蓝球按随机顺序铺满 1–16，再从头循环。
- 红球按“被使用次数最少优先”分配；红球集合不重复。
- 保存只写入号码，不自动记录购买；买完仍需在号码上点「记录购买」。
- 所有号码由 `SecureRandom` 生成，覆盖策略只决定组合分布。

## 任意奖概率估算

单注 6+1：

```
P(任意奖) = 1/16 + (15/16) × P(红球 ≥ 4)
          = 6.709%
```

`P(红球 ≥ 4) = 5,428 / 1,107,568 = 0.490%`。

n 注、蓝球全不同：

```
P(任意奖) = n/16 + (1 - n/16) × [1 - (1 - 0.490%)^n]
```

| 注数 | 成本 | 任意奖概率 |
|---:|---:|---:|
| 1 | 2 元 | 6.71% |
| 2 | 4 元 | 13.36% |
| 3 | 6 元 | 19.94% |
| 5 | 10 元 | 32.92% |
| 10 | 20 元 | 64.3% |
| 16 | 32 元 | 100% |

16 注覆盖全部蓝球时，必有一注蓝球命中，至少中六等奖（5 元）；但 32 元成本远高于
保底 5 元，长期期望仍为负。

## 实现

- 规则与生成：`core:model/rules/CoveragePlanner.kt`
- 单测：`core:model/src/test/.../CoveragePlannerTest.kt`
- UI：`feature:ticket/CoverageSheet.kt`，入口在选号页「预算覆盖」卡。
- 保存：`TicketViewModel.saveCoverage`，每注一条 `ticket` 记录，备注形如
  `覆盖 10元 · 1/5`。

## 边界

- 任意奖概率按独立红球集合估算；实际开奖每期独立，不能保证短期结果。
- 覆盖多注会线性增加成本；不要把它当成“提高回报率”。
- 不建议把覆盖方案自动标记为已购买，避免账本虚增。
